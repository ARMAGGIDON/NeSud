# NeSud

Судоку для Windows та браузера на .NET 10. WPF-клієнт працює офлайн, вебклієнт використовує серверні ігрові сеанси. Обидва клієнти використовують спільний рушій C#.

## Структура вихідного коду

```text
src/
  NeSud.Core/
    Contracts/        DTO та контракти між клієнтом і сервером
    Gameplay/         стан гри, ходи, ресурси й оцінка
    Puzzles/          генерація та логічний розв'язувач
    Persistence/      моделі локального стану
  NeSud.Storage/      SQLite та локальне збереження
  NeSud.Server/
    Endpoints/        групи HTTP API за призначенням
    Persistence/      сховища акаунтів, сеансів, історії, статистики,
                      нагород, турнірів, профілів і друзів
    Sessions/         контракти запитів та серверні сеанси
    wwwroot/
      js/             скрипти за функціональними областями
      index.html
      style.css
    Program.cs        композиція та конфігурація сервера
  NeSud/
    Windows/Main/     компонування, відображення, ігрова логіка,
                      мережеві операції та окремі діалоги WPF
tests/
  NeSud.SmokeTests/
    Scenarios/        незалежні тестові сценарії
    Program.cs        точка входу та порядок запуску
  api-smoke.ps1       перевірка HTTP API
```

C# partial-класи зберігають спільний стан вікна та сховища без зміни їхніх контрактів; розділення файлів не створює нових процесів або БД. Вебскрипти завантажуються як класичні відкладені скрипти у визначеному в HTML порядку. Стиль коду зафіксовано в `.editorconfig` (UTF-8, LF, 4 пробіли, пробіли навколо бінарних операторів, дужки C# на окремих рядках).

## Запуск

Потрібен .NET 10 SDK. У першому терміналі:

```powershell
dotnet run --project src/NeSud.Server -- --urls http://localhost:5080
```

Вебверсія: http://localhost:5080. У другому терміналі (Windows):

```powershell
dotnet run --project src/NeSud
```

Для IDE: NeSud.slnx. Вхід або реєстрація доступні в обох клієнтах. Логін: 3–32 латинські літери, цифри, крапка, підкреслення або дефіс; також підтримуються email до 254 символів. Логіни унікальні без урахування регістру. Пароль: 10–128 символів; при реєстрації потрібне підтвердження. Email не виводиться в публічному рейтингу. Desktop зберігає токен через Windows DPAPI (CurrentUser), пароль не зберігає. Вебдемо не потребує реєстрації, його тимчасові сеанси живуть у пам’яті сервера до двох годин неактивності й не потрапляють до історії акаунтів або рейтингу.

Адреса сервісу не налаштовується через GUI. Для розробки за замовчуванням використовується localhost:5080. Для релізу задайте HTTPS-адресу під час складання: `dotnet publish src/NeSud -c Release -p:NeSudServerUrl=https://your-domain.example`. Для локального адміністрування можна використати змінну `NESUD_SERVER_URL`. Desktop автоматично перевіряє доступність API та повторює синхронізацію після відновлення зв’язку; відкрита таблиця рейтингу оновлюється кожні 30 секунд.

## Архітектура

- NeSud.Core: генерація полів з єдиним розв’язком, правила, історія ходів, нотатки, оцінки.
- NeSud.Storage: SQLite, транзакції, локальний стан, історія та черга синхронізації.
- NeSud.Server: ASP.NET Core API, SQLite серверна БД, реєстрація, вхід, сесії, рейтинг, статичний адаптивний вебклієнт.
- NeSud: WPF, локальна офлайн-гра, власні тематичні діалоги, історія, статистика й акаунт.

Клієнтська БД: `%LOCALAPPDATA%/NeSud/client.db`. Старий state.json імпортується один раз, якщо БД порожня. Серверна БД: `src/NeSud.Server/data/server.db` (налаштування Database змінює шлях). Усі термінальні спроби мають UUID; запис історії ідемпотентний. Клієнт надсилає чергу завершених/перерваних спроб та резервну копію поточної гри приблизно кожні 30 секунд після входу. Серверні історії завантажуються в локальний профіль. Гостьові записи можна імпортувати в акаунт явно. Поточна спроба попереднього профілю архівується при перемиканні. Незавершені desktop-сеанси показуються у вебісторії, але поки не відкриваються для продовження в іншому клієнті.

Вебверсія виконує ходи на сервері. Браузер зупиняє керування за відсутності з’єднання; heartbeat кожні 6 секунд активної гри. Після 12 секунд без heartbeat сервер трактує сеанс як призупинений при наступному зверненні. Успішні ходи вже збережені; після відновлення з’єднання потрібне явне продовження. Ревізія захищає від застарілих ходів з іншої вкладки. Короткий розрив до 12 секунд може врахуватися в таймері. Серверна та desktop-гра мають незалежні поточні сеанси.

## Оцінка та рейтинг

Оцінка нової гри (правила v3): max(0, база + бонус − floor(секунди / 3) − 75 × помилки − 150 × підказки − штраф за кандидати − 100 × відновлені життя − 20 × автозаповнені клітинки). База: 1000/2000/3000/4000. Бонус нараховується при перемозі: round(0.6 × база × max(0, 1 − час / T)²), де T = 480/720/1200/1800 секунд. Історичні завершені ігри зберігають попередні оцінки. Перервані та програні спроби: 0 балів. Серверний рейтинг враховує завершені серверні ігри, загальний рейтинг також включає неперевірені офлайн-результати. Сервер записує приватний аудит швидкості прийнятих ручних вводів (таблиця speed_audit); результати, що задовольняють консервативну евристику нереалістичної серії, не включаються до рейтингу, порівнянь та щоденних перемог. Ознака аудиту не передається клієнтам. Це евристика, а не доказ читерства. Після завершення клієнти показують підсумок та статистичне порівняння за тією ж складністю і версією оцінювання.

## Життя, допомога та винагороди

Нова гра починається з 3 життів, 1 підказки і 1 автоматичного заповнення кандидатів. Кожна неправильна цифра забирає життя; звичайні нотатки безкоштовні. При нулі життів поле блокується, таймер зупиняється, показується поразка. Є один 10-секундний шанс розпочати рекламний перегляд для +1 життя; натискання витрачає шанс навіть при скасуванні або недоступності реклами. Якщо час минув або перегляд не завершено, поразка остаточна. Після відновлення додаткового шансу немає. Життя не можна отримувати зі сховища або в ході звичайної гри. Старі бонусні життя конвертуються у підказки 1:1. Перемикач автозавершення автоматично заповнює від 1 до 9 останніх порожніх клітинок, якщо всі введені цифри правильні; ціна 20 балів за клітинку, без зміни таймера. Undo/Redo не повертають життя, витрачені підказки, кандидати чи бали. Автокандидати коштують 2 бали за кожну додану або видалену цифру-кандидата. Наявні правильні нотатки не штрафуються; якщо змін немає, ресурс не витрачається. Ресурси зберігаються у стані гри, максимальний запас кожного ресурсу 3. Винагорода за демонстраційну рекламу: 8 секунд, після чого користувач підтверджує отримання. Сервер перевіряє час і одноразовість видачі, desktop перевіряє локальний таймер. Це заглушка без реальної рекламної мережі. Щоденні нагороди акаунта: за 1-шу та 3-тю різні перемоги дня один набір з картками ×1, ×1, ×2, за 7-му один набір з картками ×3, ×3, ×3. Нагороди за вхід немає. Кожен набір містить 3 приховані картки; обирається лише одна. Перші дві картки до перемішування містять різні типи ресурсу (підказки та автокандидати); третя містить один з них з однаковою ймовірністю. Сервер випадково перемішує позиції та зберігає склад набору до вибору. Максимум за день: 3 набори, 9 карток, 7 одиниць ресурсу; мінімум при отриманні всіх трьох наборів: 5 одиниць. Раніше нараховані набори та баланс не змінюються; старі набори враховуються під час визначення права на нові нагороди за той самий день. Для таких перехідних днів попередні нарахування можуть відрізнятися від нових лімітів. Невибрані набори зберігаються між днями. День визначається сервером за Europe/Kyiv. Перемоги рахуються за різними головоломками в поточному дні з історії акаунта, включаючи синхронізовані desktop-ігри; офлайн-перемоги, синхронізовані пізніше, відкривають нагороди за дату їх завершення. Дата офлайн-записів є клієнтською та не має гарантій античиту. Спільне сховище акаунта зберігає ресурси між іграми; поповнення поточної гри зі сховища вимагає онлайн-з’єднання, а локальна гра й демонстраційна реклама доступні офлайн. Якщо підтвердження списання ресурсу desktop переривається, клієнт зберігає UUID операції та тимчасово блокує зміну гри до повторного підтвердження. Вебсайт відкриває стартовий екран без гри; відновлена гра залишається на паузі, а вхід та реєстрація доступні в модальному діалозі. На desktop-розмірах вебполе масштабується за висотою viewport; на вузьких мобільних екранах допускається прокрутка.

## Турніри та статистика

Тиждень починається в понеділок за Europe/Kyiv. Рейтинг турніру підсумовує серверні бали за тиждень, включно зі щоденними іграми за фактичною датою завершення; однакові бали розділяються кількістю перемог, потім стабільним порядком логінів. Місця 1–2 отримують один набір з картками ×3, ×3, ×3; місце 3: ×3, ×3, ×2; місця 4–10: ×2, ×2, ×2; місця 11–30: ×1, ×1, ×2. Місця 31+ без нагороди. Максимум звичайних і турнірних винагород за повний тиждень: 22 набори, 66 карток, 52 одиниці ресурсу. Разом із сімома наборами за щоденні ігри відповідних семи дат: 29 наборів, 87 карток, 73 одиниці ресурсу (без реклами, початкових ресурсів та наздоганяння раніших дат). Раніше закриті турніри не перераховуються. Закриті тижні фіксуються транзакційно під час наступного звернення до нагород або турніру; перший турнір починається з тижня встановлення оновлення. Призові набори доступні окремо від щоденних. Ідеальна перемога: без помилок, підказок, автокандидатів, автозавершення та відновлення. Поразка або перервана спроба обнуляє поточну серію. Публічні статистики мають серверний і загальний режими.

## Щоденні ігри та місячні кубки

Окремий онлайн-режим для зареєстрованих гравців: одна спільна головоломка на календарну дату за Europe/Kyiv з випадковою складністю (Medium, Hard або Expert, по 1/3). Вибір фіксується перед генерацією; повторна спроба не змінює його. Сервер зберігає головоломку та окремий сеанс для кожного акаунта і дати; звичайна гра не замінюється. Можна повторювати невдалі спроби і проходити пропущені дні поточного місяця, але майбутні дні та минулі місяці недоступні для гри. Нагорода за першу зараховану перемогу кожної дати: один набір із трьох карток. Кількість кожної картки незалежно: ×1 (65%), ×2 (30%), ×3 (5%). У 5% наборів лише один випадковий тип ресурсу; в інших гарантовано обидва типи. Нараховані раніше набори не змінюються. Завершені спроби обох режимів потрапляють до єдиної історії, загальної статистики, рейтингу та тижневих турнірів. Звичайні щоденні пороги 1/3/7 враховують лише звичайні ігри. Старі записи challenge_attempts переносяться в history з ознакою challengeDay транзакційно, без дублювання. За всі календарні дні одного місяця видається один декоративний кубок (включно з 29 лютого у високосний рік). Кубок не дає ресурсів або балів. Перемога, набір і кубок фіксуються атомарно, з унікальними ключами дати і місяця. Після оновлення можна пройти всі вже доступні дні поточного місяця.

Публічний профіль відкривається з рейтингу або турніру; власний профіль з меню акаунта. Показує кубки, кількість щоденних перемог, звичайну накопичувальну статистику та історію обох режимів сторінками по 50 завершених/перерваних спроб. Email маскується; сервер не передає розв'язки, повні ігрові об'єкти, токени, внутрішній аудит або стан незавершеної гри. Приватна історія і її інкрементальна синхронізація містять обидва режими. Desktop має окреме нативне вікно щоденної гри, яке використовує авторитетний серверний стан, як і Web. У цьому режимі офлайн-гра недоступна.

## Головне меню, складність і друзі

Обидва клієнти відкривають головне меню; звичайна гра відновлюється лише після явного переходу. Для кожної складності профіль і рейтинг підтримують незалежні перемоги, ідеальні перемоги, бали, поточну і найкращу серію. Серія складності ігнорує спроби інших складностей. Загальна статистика збережена. Пошук за публічним іменем, запити у друзі, прийняття, відхилення, скасування і видалення доступні в обох клієнтах; лише адресат може прийняти чи відхилити запит. Email не використовується для публічного пошуку.

Нові головоломки перевіряються на єдиний розв'язок і розв'язуваність логічним алгоритмом. Легка: naked singles; середня: naked/hidden singles; складна: додатково locked candidates та naked pairs; експерт: X-Wing та логічне виключення кандидата через суперечність, доведену послідовністю singles. Складні й експертні головоломки повинні потребувати відповідного рівня технік. Необмежений перебір не використовується для класифікації. Збережені головоломки не перегенеровуються. Генерація обмежена таймаутом; відповідність рівню має пріоритет перед видачею будь-якої головоломки.

Окремі серверні сеанси щоденних ігор зберігаються для кожної дати поточного місяця, до 31 сеансу плюс одна звичайна вебгра. На межі місяця старі сеанси видаляються при запуску сервера або відкритті календаря, але історія завершених спроб, перемоги, кубки та винагороди залишаються. Звичайна офлайн-гра Desktop як і раніше має власний локальний стан, а не спільний із вебгрою.

## Ефективність

Індекси історії за датою, джерелом, складністю, версією правил, чергою нагород і терміном токена. Щоденні перемоги агрегуються SQL, порівняння не десеріалізує повні об'єкти гри. Desktop отримує нові записи сторінками до 100 через курсор, який тримається в пам'яті процесу; після перезапуску завантажує історію повторно. Незмінні чернетки не надсилаються повторно. Активна вебгра використовує heartbeat кожні 6 с, звичайний heartbeat повертає лише таймер і бали; локальний монотонний годинник оновлює індикатор між відповідями. Паузи та завершені ігри не опитуються (виняток: незавершений останній шанс або рекламний сеанс). Сервер залишається авторитетним щодо часу, стану та нагород. Реальні ходи і heartbeat досі записуються в SQLite, глобальне блокування сеансів не замінене. 

## Розгортання

```powershell
docker compose up -d --build
```

Порт 5080 прив’язано до loopback, дані в постійному Docker volume. Для доступу з інтернету потрібен HTTPS reverse proxy, обмеження запитів, резервне копіювання, моніторинг і захист доступу до хоста. Не публікуйте незахищений HTTP. Паролі хешуються PBKDF2-SHA256 із випадковою сіллю; сервер зберігає лише хеш випадкового токена доступу. API входу обмежує частоту запитів. SQLite орієнтовано на один серверний екземпляр.

## Перевірка

```powershell
dotnet build NeSud.slnx
dotnet run --project tests/NeSud.SmokeTests -c Release -- 3
```

Серверний smoke-тест: `pwsh -File tests/api-smoke.ps1` (на окремій тестовій БД, створює тестові акаунти).

Перевірте реєстрацію, обидва клієнти, завершення/переривання гри, повторну синхронізацію без дублікатів, ізоляцію профілів, від’єднання мережі під час вебгри, відновлення після перезапуску сервера. Клавіатурне керування: стрілки, цифри, N/Space, H, A, P/Esc, Ctrl+Z/Y; у WPF також Ctrl+N і F1.

## Акаунт, аватар та запрошення

Нові акаунти потребують окремого нікнейму та унікального email. Вхід можливий за обома. Ідентифікатор акаунта незмінний, нікнейм можна редагувати без втрати історії, ресурсів або друзів. Старі акаунти мігрують без зміни ключів; непідтверджену пошту можна додати в профілі. Підтверджений email у цій версії незмінний.

Для реальної відправки коду підтвердження налаштуйте SMTP через змінні середовища сервера (STARTTLS):

```powershell
$env:Smtp__Host = 'smtp.example.org'
$env:Smtp__Port = '587'
$env:Smtp__From = 'nesud@example.org'
$env:Smtp__User = 'nesud@example.org'
$env:Smtp__Password = '<SMTP password>'
```

Після реєстрації клієнт відкриває налаштування профілю та намагається надіслати код. Код діє 30 хвилин; повторне надсилання не частіше разу на хвилину. Без SMTP підтвердити пошту через клієнт неможливо. Після підтвердження доступне персональне посилання `?invite=...`. Запрошений реєструється за посиланням або вводить код вручну в Desktop, підтверджує власний email, і запрошувач одержує 3 підказки та 3 кандидати одноразово. Зарахування та поповнення гаманця виконуються в одній транзакції. Для публічного розгортання потрібен HTTPS та доступний зовні URL сервера.

Аватар: JPG/JPEG/PNG/SVG до 5 МБ, квадратне кадрування з масштабом і зміщенням. На сервер надсилається лише PNG 256 × 256. Desktop використовує Svg.Skia для самодостатніх SVG; активні або зовнішні ресурси, стилі та фільтри відхиляються.

Зміна нікнейму, додавання/видалення аватара, пошук гравців та всі операції з друзями доступні лише після підтвердження email. Обидва учасники дружби мають бути верифіковані. Публічні профілі та рейтинги залишаються доступними для перегляду. Старі зв’язки не видаляються; вони доступні після верифікації обох учасників. Для кожного акаунта існує один незмінний код запрошення, що може використовуватися багаторазово різними новими гравцями. Зміна нікнейму, повторний вхід чи перезапуск сервера не змінюють код. Незмінність забезпечує також тригер SQLite.

## SignalR + WebSocket + MessagePack

Вебклієнт використовує один WebSocket на вкладку для знімків стану, створення гри, ходів і heartbeat. Hub приймає лише WebSocket і MessagePack. REST залишається для Desktop, акаунтів, історії та нагород. Обидва транспорти використовують спільні авторитетні операції та ревізії. Непідтверджена команда не повторюється автоматично. Відновлення виконується через повний знімок. Ходи повертають змінені поля, heartbeat без змін повертає компактні дані таймера. Інші вкладки отримують сповіщення та завантажують відповідний сеанс через Observe, без запису стану та продовження таймера. Сповіщення об'єднуються на клієнті. Ігровий heartbeat раз на шість секунд залишається для контролю активності, незалежно від транспортного keep-alive.

Перед першою локальною збіркою (рекомендовано Node.js 22):

```powershell
npm --prefix src/NeSud.Server install --ignore-scripts --no-audit --no-fund
npm --prefix src/NeSud.Server run prepare-web
npm --prefix src/NeSud.Server run test:realtime
dotnet build NeSud.slnx
```

Після запуску сервера на http://localhost:5080:

```powershell
npm --prefix src/NeSud.Server run test:realtime:live
```

Тест перевіряє бінарне з'єднання, авторизацію, ізоляцію гостьових сеансів, дельти, конфлікт ревізій, сповіщення після REST-операції та відкликання токена.

Docker готує браузерні бібліотеки в окремому Node-етапі. Бібліотеки обслуговуються локально, без CDN. Для production потрібен HTTPS/WSS. Токен передається в Subscribe, а не URL. Захищені виклики перевіряють токен. Desktop залишається на REST, включно з офлайн-синхронізацією. Розраховано на один серверний процес; масштабування потребує спільного стану та backplane.
