# NeSud

Судоку для Windows та браузера на .NET 10. WPF-клієнт працює офлайн, вебклієнт використовує серверні ігрові сеанси. Обидва клієнти використовують спільний рушій C#.

## Запуск

Потрібен .NET 10 SDK. У першому терміналі:

```powershell
dotnet run --project src/NeSud.Server -- --urls http://localhost:5080
```

Вебверсія: http://localhost:5080. У другому терміналі (Windows):

```powershell
dotnet run --project src/NeSud
```

Для IDE: NeSud.slnx. Вхід або реєстрація доступні в обох клієнтах. Логін: 3–32 латинські літери, цифри, крапка, підкреслення або дефіс; також підтримуються email до 254 символів. Логіни унікальні без урахування регістру. Пароль: 10–128 символів; при реєстрації потрібне підтвердження. Email не виводиться в публічному рейтингу. Desktop зберігає токен через Windows DPAPI (CurrentUser), пароль не зберігає. Вебдемо не потребує реєстрації, його тимчасові сеанси живуть у пам’яті сервера до двох годин неактивності й не потрапляють до історії акаунтів або рейтингу.

Адреса сервісу не налаштовується через GUI. Для розробки за замовчуванням використовується localhost:5080. Для релізу задайте HTTPS-адресу під час складання: `dotnet publish src/NeSud -c Release -p:NeSudServerUrl=https://your-domain.example`. Для локального адміністрування можна використати змінну `NESUD_SERVER_URL`. Desktop автоматично перевіряє доступність API та повторює синхронізацію після відновлення зв’язку; відкрита таблиця рейтингу оновлюється кожні 10 секунд.

## Архітектура

- NeSud.Core: генерація полів з єдиним розв’язком, правила, історія ходів, нотатки, оцінки.
- NeSud.Storage: SQLite, транзакції, локальний стан, історія та черга синхронізації.
- NeSud.Server: ASP.NET Core API, SQLite серверна БД, реєстрація, вхід, сесії, рейтинг, статичний адаптивний вебклієнт.
- NeSud: WPF, локальна офлайн-гра, власні тематичні діалоги, історія, статистика й акаунт.

Клієнтська БД: `%LOCALAPPDATA%/NeSud/client.db`. Старий state.json імпортується один раз, якщо БД порожня. Серверна БД: `src/NeSud.Server/data/server.db` (налаштування Database змінює шлях). Усі термінальні спроби мають UUID; запис історії ідемпотентний. Клієнт надсилає чергу завершених/перерваних спроб та резервну копію поточної гри приблизно кожні 30 секунд після входу. Серверні історії завантажуються в локальний профіль. Гостьові записи можна імпортувати в акаунт явно. Поточна спроба попереднього профілю архівується при перемиканні. Незавершені desktop-сеанси показуються у вебісторії, але поки не відкриваються для продовження в іншому клієнті.

Вебверсія виконує ходи на сервері. Браузер зупиняє керування за відсутності з’єднання; heartbeat кожні 3 секунди. Після 12 секунд без heartbeat сервер трактує сеанс як призупинений при наступному зверненні. Успішні ходи вже збережені; після відновлення з’єднання потрібне явне продовження. Ревізія захищає від застарілих ходів з іншої вкладки. Короткий розрив до 12 секунд може врахуватися в таймері. Серверна та desktop-гра мають незалежні поточні сеанси.

## Оцінка та рейтинг

Оцінка нової гри (правила v3): max(0, база + бонус − floor(секунди / 3) − 75 × помилки − 150 × підказки − штраф за кандидати − 100 × відновлені життя − 20 × автозаповнені клітинки). База: 1000/2000/3000/4000. Бонус нараховується при перемозі: round(0.6 × база × max(0, 1 − час / T)²), де T = 480/720/1200/1800 секунд. Історичні завершені ігри зберігають попередні оцінки. Перервані та програні спроби: 0 балів. Серверний рейтинг враховує завершені серверні ігри, загальний рейтинг також включає неперевірені офлайн-результати. Сервер записує приватний аудит швидкості прийнятих ручних вводів (таблиця speed_audit); результати, що задовольняють консервативну евристику нереалістичної серії, не включаються до рейтингу, порівнянь та щоденних перемог. Ознака аудиту не передається клієнтам. Це евристика, а не доказ читерства. Після завершення клієнти показують підсумок та статистичне порівняння за тією ж складністю і версією оцінювання.

## Життя, допомога та винагороди

Нова гра починається з 3 життів, 1 підказки і 1 автоматичного заповнення кандидатів. Кожна неправильна цифра забирає життя; звичайні нотатки безкоштовні. При нулі життів поле блокується, таймер зупиняється, показується поразка. Є один 10-секундний шанс розпочати рекламний перегляд для +1 життя; натискання витрачає шанс навіть при скасуванні або недоступності реклами. Якщо час минув або перегляд не завершено, поразка остаточна. Після відновлення додаткового шансу немає. Життя не можна отримувати зі сховища або в ході звичайної гри. Старі бонусні життя конвертуються у підказки 1:1. Перемикач автозавершення автоматично заповнює від 1 до 9 останніх порожніх клітинок, якщо всі введені цифри правильні; ціна 20 балів за клітинку, без зміни таймера. Undo/Redo не повертають життя, витрачені підказки, кандидати чи бали. Автокандидати коштують 2 бали за кожну додану або видалену цифру-кандидата. Наявні правильні нотатки не штрафуються; якщо змін немає, ресурс не витрачається. Ресурси зберігаються у стані гри, максимальний запас кожного ресурсу 3. Винагорода за демонстраційну рекламу: 8 секунд, після чого користувач підтверджує отримання. Сервер перевіряє час і одноразовість видачі, desktop перевіряє локальний таймер. Це заглушка без реальної рекламної мережі. Щоденні нагороди акаунта: вхід ×1, перша перемога ×1, третя ×1, сьома ×3. Кожен набір містить 3 приховані картки; обирається лише одна. Картка містить випадкові підказки або автокандидати, 1–3 одиниці. Невибрані набори зберігаються між днями. День визначається сервером за Europe/Kyiv. Перемоги рахуються за різними головоломками в поточному дні з історії акаунта, включаючи синхронізовані desktop-ігри; офлайн-перемоги, синхронізовані пізніше, відкривають нагороди за дату їх завершення. Дата офлайн-записів є клієнтською та не має гарантій античиту. Спільне сховище акаунта зберігає ресурси між іграми; поповнення поточної гри зі сховища вимагає онлайн-з’єднання, а локальна гра й демонстраційна реклама доступні офлайн. Якщо підтвердження списання ресурсу desktop переривається, клієнт зберігає UUID операції та тимчасово блокує зміну гри до повторного підтвердження. Вебсайт відкриває гостьову гру одразу, а вхід та реєстрація доступні в модальному діалозі. На desktop-розмірах вебполе масштабується за висотою viewport; на вузьких мобільних екранах допускається прокрутка.

## Розгортання

```powershell
docker compose up -d --build
```

Порт 5080 прив’язано до loopback, дані в постійному Docker volume. Для доступу з інтернету потрібен HTTPS reverse proxy, обмеження запитів, резервне копіювання, моніторинг і захист доступу до хоста. Не публікуйте незахищений HTTP. Паролі хешуються PBKDF2-SHA256 із випадковою сіллю; сервер зберігає лише хеш випадкового токена доступу. API входу обмежує частоту запитів. SQLite орієнтовано на один серверний екземпляр.

## Перевірка

```powershell
dotnet build NeSud.slnx
dotnet run --project tests/NeSud.SmokeTests -c Release -- 3
```

Серверний smoke-тест: `pwsh -File tests/api-smoke.ps1` (на окремій тестовій БД, створює тестові акаунти).

Перевірте реєстрацію, обидва клієнти, завершення/переривання гри, повторну синхронізацію без дублікатів, ізоляцію профілів, від’єднання мережі під час вебгри, відновлення після перезапуску сервера. Клавіатурне керування: стрілки, цифри, N/Space, H, A, P/Esc, Ctrl+Z/Y; у WPF також Ctrl+N і F1.
